# Двухногий подсчёт — поэтапное включение в Release

## Цель

Внедрить в обычную iOS-сборку ранее проверенный на устройстве двухногий счётчик, **не заменяя** проверенную 2D реализацию без дополнительных испытаний. Этот Draft PR создан напрямую от `main`, отдельно от исследовательских Draft PR #26 (Vision 3D), #28 (Pose Replay) и #29 (Debug live bilateral).

## Как работает переключение

- В Release и Debug перед началом тренировки отображается кнопка **«2Н»**. По умолчанию она **выключена**, активен **исходный 2D**.
- При каждом включении показывается предупреждение о том, что двухногий подсчёт ещё экспериментальный. После подтверждения надпись кнопки становится синей.
- **До «Старт»** можно в любой момент нажать «2Н» ещё раз и вернуться к старому 2D. Это и есть **немедленный откат на следующую тренировку без переустановки приложения**.
- **После «Старт» переключение заблокировано**, чтобы статистика одной тренировки не смешивала два несовместимых алгоритма.
- Выбор **не сохраняется между новыми тренировками**: каждая начинается в старом режиме. Это намеренно безопасная первая стадия rollout; только после дополнительных тестов можно отдельно изменить значение по умолчанию или сохранять явный выбор.
- При отказе от двухногого счётчика или обнаружении новых FP достаточно до новой тренировки **оставить «2Н» выключенной**. Изменений сервера, удалённых конфигураций и новой установки не требуется.

## Счётчики

**Обычный 2D** использует `PoseAnalyzer`, который выбирает одну надёжную ногу, и `SquatCounter(maximumHipKneeHeightRatio: 0.35)`. Этот путь всегда доступен, не меняет пороги и соответствует `main`.

**«2Н»** запускает два независимых экземпляра `PoseAnalyzer` и `SquatCounter` — отдельный на левые hip/knee/ankle и на правые. Если две ноги подтверждают **одно** движение, события с перекрывающимися фазами `lowered → standing` и разницей времени count ≤0,75 с объединяются. Данные от одной стороны не объединяются друг с другом.

Для объединения применяется **отложенная фиксация до ~0,75 с**. В приложении счёт может обновляться с небольшой задержкой. При паузе и ручном завершении ожидания учитываются однократно. При потере суставов/разрыве или смене ракурса отслеживание фазы сбрасывается, чтобы старое движение не завершилось позднее. В историю сохраняется результат выбранного режима.

Это эвристика, которая ранее показала преимущества на тестах, но **не гарантирует** корректный подсчёт при любых ракурсах и темпах.

## Уже подтверждено экспериментами

- 2 исходных числовых Replay на настоящем iPhone: условные TP/FP/FN исходного 2D **7/0/5**, bilateral **11/0/1** суммарно по предварительно визуально размеченным 24 движениям.
- Live Debug «2Н» в PR #29: 6 полных засчитаны, 6 неполных не засчитаны в одном проходе; legacy в отдельной сессии при том же протоколе засчитал 3 полных и пропустил 3 после поворота.
- Дополнительная Debug-запись: один полный присед → пауза → продолжение → ещё один полный → неполный не засчитан; итог **2**, обе записи тренировок видны в истории.
- Пользователь подтвердил полный набор XCTest и `Product → Build For → Profiling` **Build Succeeded** для **PR #29**. Это **не** результаты сборки данного нового Release PR.

По этим тестам **нельзя** заявлять независимую биомеханическую ground truth, универсальный recall/precision или точность для новых пользователей и движений.

## Обязательные проверки именно этой ветки

1. В Fork открыть `feature/bilateral-release-opt-in` от `main`, `Fetch → Pull`.
2. Выполнить **полный `⌘U`**: существующие XCTest плюс новые тесты Release-переключения, pause/resume, pending count, legacy fallback и истории.
3. Выполнить `Product → Build For → Profiling`: подтвердить Release-компиляцию с новым счётчиком и кнопкой.
4. Запустить Debug на iPhone. Проверить, что кнопка «2Н» до старта **белая**; при первом нажатии появляется предупреждение, подтверждение делает надпись синей; до старта второй клик возвращает белый. После запуска кнопка неактивна.
5. С включённым «2Н»: 3 полных + 3 неполных боком, 3 полных + 3 неполных после поворота (~45° и при возможности фронтально). После последнего движения выждать 1 с и завершить. Ожидается **6 засчитанных** из 12, но это критерий теста, не гарантия.
6. Повторить с **выключенным «2Н»** на новой тренировке и сравнить ошибки. Проверить паузу, продолжение, сохранение в истории.
7. Запустить именно **Release-версию** на устройстве перед публикацией: убедиться, что кнопка «2Н» доступна, режим legacy включён по умолчанию и при выключенной «2Н» подсчёт не изменился.
8. Только после успешного теста этой ветки и оценки риска новых FP решать, готов ли Draft PR к объединению в `main`.

- Не добавляли Vision 3D, Replay, запись JSON, облачную синхронизацию и сбор телеметрии.

- Не добавляли удалённый feature flag; откат выполняется локальным переключателем перед новой тренировкой.
