# Pose Replay — воспроизводимая проверка приседаний

## Задача

Изменять алгоритм только после сравнения на **одинаковых входных кадрах**. В этой первой версии Replay фиксирует числовые координаты hip/knee/ankle для обеих ног **после Vision 2D**, то есть поток `BodyPose` непосредственно перед `PoseAnalyzer` и `SquatCounter`. Replay воспроизводит 2D классификацию на тех же координатах и с тем же временем кадров, включая события сброса движения. Экспериментальный Vision 3D из Draft PR #26 **не входит** в эту первую версию.

## Как записать материал на iPhone

1. В Fork открыть ветку `feature/pose-replay-baseline`, в Xcode выполнить `⌘U`, затем Debug `⌘R`.
2. Установить iPhone на устойчивую опору, чтобы **всё тело и ноги** были в кадре. На первом проходе стоять боком к камере. Нажать `Старт`.
3. Нажать кнопку **REC**, прочитать предупреждение о данных о движениях тела, подтвердить `Начать запись`. Запись **не включается автоматически** и не сохраняет фотографии/видеокадры.
4. Постой 2–3 секунды, затем выполни **3 полных, 3 неполных** приседания боком. Встань неподвижно на 2–3 секунды между сериями. При необходимости повернись под 45° и повтори 3+3 (не меняй высоту телефона).
5. Нажми **STOP**, затем выбери `Сохранить в Файлы` или другую опцию системного share sheet. Получится файл `RepsCounter-PoseReplay-….json` c координатами суставов и относительными метками времени. Временный файл приложения удаляется после закрытия меню экспорта.
6. **При желании** одновременно записать экран, чтобы позднее вручную разметить каждую попытку. Видео и экспортированный JSON в GitHub автоматически не отправляются. Для анализа можно передать JSON и видео **отдельно в разговор**, если согласен поделиться числовыми данными тела.

Система записывает **максимум 1200 событий** (примерно две минуты при 10 позах/с). Дальнейшие события не добавляются до STOP. Для длинных сессий начни новый экспорт.

## Что содержит JSON

`schemaVersion: 1`, `events` (время от ручного начала записи, вид `pose` или `reset` и для pose: aspect ratio, угол вращения и координаты/уверенность суставов `leftHip`, `leftKnee`, `leftAnkle`, `rightHip`, `rightKnee`, `rightAnkle`), `annotations` (по умолчанию пустой массив). В данных **нет пикселей камеры, видео или аудио**, но координаты движений тела **являются персональными данными контекста тренировки**, поэтому не публикуй такие файлы в открытом репозитории без явного решения.

`annotations` — необязательные **ручные** временные границы попыток, каждая `{ "startSeconds": ..., "endSeconds": ..., "isFullSquat": true/false }`. Диапазоны неперекрывающиеся. Если приседание физически полное, но алгоритм не засчитал его — FN. Если неполное засчитано — FP. Дополнительное засчитывание в одной полноценной попытке тоже FP. События вне размеченных попыток считаются FP. Пока диапазоны не размечены, **не утверждать precision/recall по числу 2D повторов**.

## Как воспроизводится алгоритм

`PoseReplayRunner.replay(session)` восстанавливает `BodyPose`, последовательно применяет `PoseAnalyzer` и текущий `SquatCounter(maximumHipKneeHeightRatio: 0.35)`, сбрасывает движение на записанных `reset`, при паузе между пригодными позами более 250 мс и при смене/потере ноги. Выдаёт точные временные метки count и диагностические `PoseReplayDepthSample`.

**Теневая проверка глубины** хранит `signedHipKneeVerticalDistance = hip.y - knee.y` по выбранной 2D ноге в нормированных координатах Vision (Y растёт вверх): значение положительно, пока **центр hip-joint выше knee-joint**; <=0 означает что эти два распознанных центра на одной высоте или тазобедренный центр ниже. Это **ещё не** биомеханический критерий «складка таза ниже верхней части колена»: 2D перспектива и неточность суставов влияют на метрику. Сравниваются **непосредственно** signed distance и старый нормализованный наклон бедра, но оба значения **не влияют на счёт**.

`PoseReplayRunner.score(result, against: annotations)` вычисляет TP, FP, FN только на вручную размеченных диапазонах. В тестовом наборе есть демонстрационные синтетические позы; они подтверждают детерминированность и корректность инфраструктуры, но **не реальную accuracy Vision**.

## Границы первой версии

- Реплей выполняется над **после-Vision 2D** наблюдениями: он не измеряет ошибки самого Vision от видеопикселей. Чтобы исследовать точность распознавания суставов, нужны визуальные референсы, полученные с отдельным явным согласием, и разметка.
- В этом PR не меняются production 2D счёт, порог 0,35, камера, Core Data или экспериментальный 3D.
- Следующим этапом после получения первого реального JSON и ручной разметки можно расширить формат до синхронных 3D числовых показателей отдельным небольшим PR (не добавлять 3D через прямое копирование 61-коммитного Draft #26).
- В Xcode обязательны `⌘U` и `Product → Build For → Profiling`; Release не содержит инструментов Replay.
