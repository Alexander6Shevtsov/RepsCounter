# Экспериментальный двухногий подсчёт в реальной тренировке

## Зачем

На двух локальных Replay-записях с предварительной визуальной разметкой по 12 движений каждая независимые 2D счётчики правой и левой ноги дали улучшение условных TP/FN без дополнительных FP:

| Запись | Legacy TP/FP/FN | Bilateral TP/FP/FN |
|---|---|---|
| Первая | 3/0/3 | 5/0/1 |
| Вторая | 4/0/2 | 6/0/0 |

Swift Replay на физическом iPhone подтвердил эти результаты для размеченных JSON, но это **не** независимая биомеханическая разметка и **не** доказательство общего качества модели. Координаты и видео пользователя не опубликованы в репозитории.

## Что делает этот Draft PR

Вся новая логика — под `#if DEBUG` и по умолчанию **выключена**. Основной production 2D, его порог глубины `0.35`, камера и Core Data в Release **не изменены**.

На экране тренировки в Debug появилась кнопка **«2Н»** рядом с диагностикой. Пока тренировка не запущена, нажатием можно включить или выключить двухногий режим. Синий цвет надписи означает включённый режим. После **«Старт»** изменить режим нельзя: это исключает смешивание результатов алгоритмов внутри подхода. Для возврата к старому алгоритму начать новую тренировку и оставить кнопку выключенной.

При включённом режиме каждый новый `BodyPose` обрабатывают два независимых `PoseAnalyzer` + два исходных `SquatCounter(maximumHipKneeHeightRatio: 0.35)`. Каждый счётчик анализирует **только три сустава своей ноги**. Результат продвигает тренировочный счёт и сохраняется в обычную историю, но только в этом Debug-тесте.

Повторения с противоположных ног объединяются при реальном перекрытии интервала от подтверждения `lowered` до `counted` и разнице времени count не более **0.75 с**. Поэтому событие задерживается до истечения окна дедупликации, что создаёт заметную задержку отображения счётчика до ~0.75 с. Это экспериментальная эвристика, а не гарантия отсутствия двойных счётов. При паузе или завершении тренировки ожидающие завершённые события учитываются один раз. При потере суставов или паузе >250 мс новое движение нельзя продолжить из прежней нижней фазы.

## Порядок проверки на iPhone

1. В Fork открыть `experiment/bilateral-live-debug` и выполнить Fetch → Pull.
2. Полный **Xcode ⌘U**. Любую ошибку компиляции или XCTest фиксировать прежде аппаратного теста.
3. **Product → Build For → Profiling** подтверждает Release без кнопки «2Н» и нового алгоритма.
4. Для первого эксперимента открыть Debug на iPhone, пока написано «Старт», включить **«2Н»**, затем запустить тренировку. Установить тот же боковой ракурс с видимыми стопами.
5. Сделать **3 полных, 3 неполных** приседания боком; затем по **3 под ~45°**, не изменяя высоту камеры. Записать экран и сравнить итоговый счёт с заранее известным количеством правильных движений.
6. Начать **новую тренировку**, не включая «2Н», и повторить точно такой же порядок при тех же условиях для Legacy. В обеих тренировках остановиться на 12 движениях и дождаться **1 секунды после последнего движения** для завершения окна дедупликации.
7. Если появились ложные повторения или сбои установки/остановки, не включать экспериментальный алгоритм в Release. Вернуться к Legacy и оставить PR Draft.

Это новый **live**-эксперимент. Воспроизведённые на Replay показатели не следует автоматически приписывать ему до тестирования на устройстве. Не объединять в main без полного XCTest, Release и сравнительного теста с однозначным количеством реальных движений.
